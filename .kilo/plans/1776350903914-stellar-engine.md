# Gym Tracker Web App - Implementation Plan

## Project Overview
Build a static, offline-first PWA for tracking gym workouts with aesthetic UI, offline storage, and optional dynamic features (weather palettes, gym tagging).

**Tech Stack:**
- Frontend: React + Next.js (Static Export)
- Styling: Tailwind CSS
- State: Zustand
- Storage: IndexedDB (Dexie.js)
- Deployment: Vercel (recommended) or GitHub Pages

---

## Phase 1: Project Setup (Week 1-2)

### 1.1 Initialize Next.js Project
- Create Next.js app with TypeScript
- Configure Tailwind CSS
- Set up project structure (`/app`, `/components`, `/lib`, `/hooks`)

### 1.2 Configure PWA
- Add `next-pwa` or manual service worker setup
- Create `manifest.json` for PWA installation
- Configure offline caching strategies

### 1.3 Set Up IndexedDB
- Install Dexie.js
- Define schema: workouts, palettes, gyms
- Create data access hooks

---

## Phase 2: Core Features (Week 3-4)

### 2.1 Workout Entry Form
- Form component: exercise name, sets, reps, duration, weight
- Validation and error handling
- Save to IndexedDB on submit

### 2.2 Workout History
- List view of past workouts
- Filter/sort functionality
- Delete/edit workouts

### 2.3 Palette System
- Create predefined color palettes (5-6 themes)
- Palette selector UI component
- Weather-based auto-selection (requires API key)

---

## Phase 3: Dynamic Features (Week 5)

### 3.1 Gym Tagging
- Location prompt on workout entry
- Geolocation API integration
- Serverless function for gym lookup (using Places API or similar)
- Offline graceful degradation

### 3.2 Weather-Based Palettes
- Serverless function to fetch weather data
- Map weather conditions to palettes
- Cache weather data to reduce API calls

---

## Phase 4: Export & Polish (Week 6)

### 4.1 Data Export
- Export workouts to CSV
- Export workouts to JSON
- Download handling

### 4.2 UI/UX Improvements
- Responsive design testing
- Accessibility: high-contrast mode, larger text
- Loading states and error messages

### 4.3 Testing & Deployment
- Test offline functionality
- Lighthouse audit (performance, accessibility)
- Deploy to Vercel

## Key Decisions
1. **Deployment**: Vercel (best Next.js + serverless support)
2. **State**: Zustand (lightweight, minimal boilerplate)
3. **Weather API**: OpenWeatherMap (free tier)
4. **Gym Lookup**: Use Places API or mock data for MVP
